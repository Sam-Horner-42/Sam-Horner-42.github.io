Stelline Compiler.

A compiler front-end for the Stelline programming language. It turns raw source text into tokens and checks them against the language grammar, and it is written in plain ANSI C with no external libraries.

Overview

Three stages that take a program from characters to a checked syntax tree.

Stelline is a small, type-safe teaching language. This project implements its compiler front-end. It reads source files efficiently, splits them into typed tokens and confirms that the token stream follows the grammar. Any error is reported with its exact line and character position.

The code uses only stdio.h, stdlib.h and string.h. There is no parser generator and no lexer library, so every stage is written by hand, including memory management.

Highlights

  • Configurable buffer

    Manages the input stream under three growth policies. It supports rollback and retract so the scanner can look ahead and back up.

  • Table-driven lexer

    A finite state automaton driven by a transition table turns characters into typed tokens and traps malformed input.

  • Recursive-descent parser

    A top-down parser checks the token stream against Stelline's context-free grammar, which is specified in EBNF.

  • Precise errors

    Diagnostics report the exact line and character, so a malformed program points you straight to the problem.

Buffer design

The buffer can grow in three ways, chosen by a mode flag. Each one trades memory against the number of reallocations:

ModeFlagBehaviour
Fixed'f'Static capacity. Rejects input at the limit.
Additive'a'Grows linearly by a fixed increment.
Multiplicative'm'Grows exponentially by a factor, so appends have amortised O(1) cost.

My contribution

This was a solo project that I wrote to help me better understand the compilation process. The parser was by far the hardest aspect of this project.

What I learned

By far the hardest part of this compiler was defining the transition table. It took likely over 100 failed compilations before the final version was reached.
